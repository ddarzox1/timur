# Qauipsiz — охрана труда (MVP)

Go + htmx + PostgreSQL. Один бинарник, шаблоны, статика и миграции встроены.

## Быстрый старт

Нужны Docker и (для запуска без Docker) Go 1.26.

```sh
make up      # создаст .env из .env.example и поднимет приложение + Postgres
```

Откройте http://localhost:8080 → «Войти»:

| ИИН | Кто | Куда попадёте |
|---|---|---|
| 900101300017 | Айгерим — админ, инженер ОТ | `/admin` |
| 900101300027 | Ерлан — монтажник | `/m` (мобильная версия) |
| 900101300037 | Данияр — прораб, ответственный за ЖК Алатау | `/m` |

Пароль демо-пользователей — **Demo1234**.

Остальные команды — `make help`:

```sh
make run         # приложение на хосте (go run) + Postgres в Docker — для разработки
make test        # все тесты, включая интеграционные
make test-unit   # быстрые тесты без базы
make lint        # gofmt + go vet
make logs        # логи контейнера
make down        # остановить
make reset       # удалить базу и загрузки (спросит подтверждение)
make up-s3       # разработка с хранением файлов в S3 (локальный S3 на SeaweedFS)
```

Все настройки — в [.env.example](.env.example) с комментариями. База — в томе `pgdata`.

## Файлы: диск или S3

Фото опасностей и чек-листов, селфи, PDF/видео инструктажей и планы эвакуации хранятся там, куда указывает `STORAGE`:

| `STORAGE` | Где лежат | Что нужно на сервере |
|---|---|---|
| `local` (по умолчанию) | `UPLOADS_DIR`, в Docker — том `uploads` | примонтировать том на `/app/uploads` |
| `s3` | приватный бакет S3-совместимого хранилища, ключ `{org}/{имя}` | `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`; том не нужен |

В обоих режимах ссылка на файл одна и та же — `/files/{org}/{имя}`, и права проверяет приложение: чужая организация получает 404. В режиме S3 после проверки приложение отвечает редиректом на подписанную ссылку, которая живёт 5 минут. Сам бакет остаётся закрытым, а трафик идёт мимо сервера приложения.

Переезд с диска на S3: скопировать содержимое `uploads/` в бакет с теми же путями (например, `aws s3 sync uploads/ s3://бакет/ --endpoint-url …`) и переключить `STORAGE=s3`. Записи в базе менять не нужно.

Для персональных данных граждан РК выбирайте хранилище в Казахстане. Этот же бакет подойдёт в Dokploy для бэкапов Postgres.

Вход выполняется строго по ИИН и паролю. При создании сотрудника система генерирует первичный пароль из 8 букв и цифр и показывает его администратору один раз. Сотрудник может сменить пароль в профиле.

Секреты и первичные пароли никогда не выводятся в журнал приложения. Для уже существующих записей без пароля доступ следует выдавать через контролируемый административный сброс, а не через startup-логи.

Сотрудник: `/m` (мобильная PWA). Инженер ОТ / админ: `/admin`.

Инструктажи подписываются ЭЦП через QR-киоск или кнопку eGov mobile. В разработке включён `SIGEX_FAKE=1`:
вместо внешнего запроса форма принимает тестовые ИИН и ФИО, но проходит тот же сценарий сопоставления,
порядка подписей и сохранения CMS. Реальный режим намеренно заблокирован до согласования production-контракта SIGEX.

## Архитектура

Чистая архитектура, зависимости направлены внутрь: `delivery → usecase → domain`, `repository → domain`.

```
cmd/server/main.go        точка входа: конфиг → БД и миграции → сборка зависимостей → HTTP-сервер (graceful shutdown)
internal/
  config/                 переменные окружения
  domain/                 сущности и правила без БД и HTTP (телефон, гео, подпись, доступ к опасности, сроки)
  usecase/                бизнес-логика; каждый пакет объявляет нужные ему интерфейсы (Repo, Storage, SMSSender)
    auth/ hazard/ induction/ checklist/ people/ dashboard/ pilot/
  repository/postgres/    реализация интерфейсов usecase на pgx; транзакции внутри методов; ports.go проверяет соответствие
  delivery/http/          маршруты, middleware (вход, роли, CSRF), разбор форм, рендер шаблонов, RU/KZ
  infra/sms, infra/storage  SMS (пока в лог) и хранение файлов на диске
web/                      шаблоны html/template + htmx и статика (embed)
migrations/               SQL-миграции goose (embed)
```

### Тесты

| Слой | Что проверяется | Нужна БД |
|---|---|---|
| `domain` | телефон, расстояние, подпись PNG, просрочка, видимость опасности | нет |
| `usecase/*` | бизнес-правила на фейковых репозиториях: вход и смена пароля, ответственный и срок опасности, права на устранение, подпись инструктажа и гео, «Нет» в чек-листе → опасность, импорт CSV, роли | нет |
| `infra/storage` | проверка типа файла по содержимому, размер, path traversal | нет |
| `repository/postgres` | фильтры реестра, журналы по видам и датам, истекающие повторные, импорт, изоляция по организации, сессии | да |
| `delivery/http` | вход по ИИН и паролю → роли, CSRF, htmx-редиректы, 400 на валидацию, изоляция организаций и файлов | да |

```sh
go test -cover ./internal/usecase/...
```

## Безопасность

- **Изоляция организаций:** каждый запрос по id фильтруется по `org_id`/`user_id` в SQL; ссылки из форм (сотрудник, объект, подразделение, шаблон) сверяются с организацией. Файлы `/files/{org}/…` отдаются только своей организации. Покрыто тестами в `repository/postgres` и `delivery/http`.
- **Роли:** сотрудник — только `/m` и свои или назначенные ему опасности; инженер ОТ — вся организация, кроме настроек; админ — всё. Админа назначает и редактирует только админ.
- **Вход:** только по уникальному ИИН и паролю; пароль хранится как bcrypt-хеш. Сессия — случайный токен; в БД хранится только его хеш; cookie `HttpOnly`, `SameSite=Lax`.
- **CSRF:** `SameSite=Lax` + проверка `Origin` у всех изменяющих запросов.
- **Заголовки:** CSP (`frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`; загруженные файлы отдаются с `CSP: sandbox`.
- **Загрузки:** тип проверяется по содержимому, до 25 МБ на файл; тело запроса ограничено (`MaxBytesReader`). Пути к файлам задаёт только сервер, а не форма.
- **Перед продом:** задать `POSTGRES_PASSWORD`, не задавать `SEED`, `COOKIE_SECURE=1` за HTTPS. Порт базы опубликован только на `127.0.0.1`.
