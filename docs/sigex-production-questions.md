# SIGEX: что подтверждено и что спросить перед production

Проверено по публичной документации SIGEX 25.11.2026.

## Уже подтверждено документацией

- Документ можно зарегистрировать первой CMS-подписью без mTLS: `POST /api`, затем передать исходный PDF в `POST /api/{id}/data` как `application/octet-stream`.
- Предрегистрация документа без подписи требует аутентификации информационной системы по mTLS.
- Следующие CMS добавляются через `POST /api/{id}`.
- При регистрации первой и последующих подписей SIGEX собирает отсутствующие OCSP и TSP.
- `buildDDC` принимает оригинальный PDF как `application/octet-stream` и работает без подключённого архива.
- DDC проверяет подписи на момент их регистрации по сохранённым OCSP/TSP.
- API документа возвращает ИИН, БИН для сертификата юрлица, subject/issuer, serial number, срок сертификата, policy/key usage, TSP и OCSP.
- QR одноразовый; срок возвращается в `expireAt`; истечение упрощённой операции даёт `fail` с `eGov signing operation expired`.
- Start: 40 документов/месяц, 5 МБ QR/DDC, до 100 активных QR-операций с одного IP, архив 5 ГБ.
- Lite: 10 000 ₸/месяц при годовой оплате или 100 000 ₸/год, без лимита документов. Pro: 1 000 000 ₸/год.
- eGov mobile и eGov Business поддерживаются.

Источники: [API документов](https://sigex.kz/support/developers/api-documents/), [базовый QR API](https://sigex.kz/support/developers/api-egov-basic/), [хранение](https://sigex.kz/support/developers/data-storage/), [тарифы](https://sigex.kz/prices/).

## Письмо поставщику

**Тема:** Qauipsiz — договорная и multi-tenant схема SIGEX для производственного ЭДО

Здравствуйте!

Qauipsiz — multi-tenant SaaS для электронных журналов инструктажей по безопасности и охране труда. Один неизменяемый PDF подписывают работник и инструктирующий через eGov mobile/business; мы сохраняем CMS, OCSP/TSP и DDC.

Технический сценарий базового API понятен из документации. Перед production просим письменно подтвердить договорные условия:

1. Может ли одна подписка/организация Qauipsiz регистрировать документы разных конечных клиентов (разные БИН) как SaaS-интегратор? Нужна ли reseller/OEM-модель или отдельная организация/подписка SIGEX для каждого клиента?
2. Кому принадлежат квоты документов и архива при такой схеме: Qauipsiz, первому подписанту или организации из `businessId` сертификата?
3. Требуется ли отдельный договор конечного клиента с SIGEX для юридических гарантий проверки, либо достаточно договора SIGEX ↔ Qauipsiz и договора поручения Qauipsiz ↔ клиент?
4. Какой SLA доступен на Lite и Pro: месячная доступность, время реакции/восстановления, плановые работы, компенсации и аварийный канал?
5. Каков гарантированный срок хранения реестра подписей, OCSP/TSP и возможности экспорта CMS, если архив оригинала не подключён?
6. Есть ли sandbox или рекомендуемый стенд для интеграционных тестов, включая успешную, отменённую, истёкшую операцию, сертификат физлица и сотрудника юрлица? Допустимы ли реальные тестовые подписи с последующим удалением/изоляцией?
7. Есть ли числовой rate limit запросов/секунду для базового API на Start/Lite и рекомендуемые правила retry/backoff/idempotency?
8. Можно ли договорно гарантировать получение обогащённой CMS `signFormat=0` с интегрированными OCSP/TSP для каждой зарегистрированной подписи?
9. Есть ли webhook для завершения/ошибки базовой или упрощённой QR-операции, либо требуется polling?
10. Просим предоставить актуальный DPA/условия обработки персональных данных, перечень ЦОД и субподрядчиков, процесс уведомления об инциденте и удаления данных.

Ожидаемый объём на старте: 20–200 документов-партий на одну компанию в месяц; далее несколько компаний в одном SaaS. Просим рекомендовать тариф и договорную модель.
